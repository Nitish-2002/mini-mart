# CR-006 — Token contract table doesn't match the published prototype's actual palette/typography (color values, dark theme, Fredoka)

**Date:** 2026-09-04
**Tasks affected:** inferred: see ## Change Summary
**Raised by:** Bhargav
**Tier:** design

## What was specified

[experience-design.md's Token contract table](../experience-design.md#4a-primary-design-primitives) fixes a flat, single-theme palette: Primary `#059669`, four neutral shades, one Error color, Inter as the only typeface, no dark-theme values.

## What reality showed

Starting [TASK-AUTH-013](../tasks.md#task-auth-013-frontend_storefront-auth-screens) (matching the real frontend to the published prototype) required reading the prototype's actual CSS custom properties to build against. They don't match the table: primary is `#12734f` (light) / `#2fa578` (dark), not `#059669` — a real color, not a rounding difference. The prototype also has a complete token set the table never captured at all: a `--gold`/`--gold-tint` pair (used for the `pending_approval` StatusBadge state), a `--brick`/`--brick-tint` pair (the actual error color, `#ae4034`, not the table's `#DC2626`), a `--shadow` token, and full dark-theme values for every one of them. The prototype also uses Fredoka for the wordmark/display moments (confirmed in [Prototype Evidence](../experience-design.md#prototype-evidence)'s own description) — Fredoka is never mentioned anywhere in the approved document.

## Impact

Building the real frontend against the table as written would produce a visually different app than the one already reviewed as the prototype — the wrong green, a harsher red, no dark-theme support, missing the pending-state gold accent, no display typeface for the wordmark. Since the prototype is the tangible artifact this project actually evaluated design fidelity against (per stage 40's own fidelity choice: "a real interactive HTML prototype, not annotated wireframes"), it is treated as the more complete, more considered source here — the table was an earlier, incomplete restatement that was never fully synced back to the finished prototype.

## Proposed resolution

Replace the Token contract table with the prototype's actual values (light + dark), add the missing Fredoka entry, and add a one-line note that `[decision-62](../experience-design.md#4a-primary-design-primitives)`'s color choice stands, only its exact hex values are corrected. No change to the underlying design intent (jade/grocery-green primary, warm neutral ground, gold/brick semantic accents) — this is a fidelity correction, not a redesign.
