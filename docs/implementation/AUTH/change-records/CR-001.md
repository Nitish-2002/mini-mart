# CR-001 — Add deactivated status for previously-approved Delivery Agents

**Date:** 2026-09-03
**Tasks affected:** TASK-AUTH-001
**Raised by:** Bhargav
**Tier:** brd

## What was specified

`business-requirements.md`'s Domain Vocabulary locked the Delivery Agent status lifecycle at three values: `pending_approval`, `approved`, `rejected` (decision-26 fixed this vocabulary as canonical and not to be re-invented downstream).

## What reality showed

While scoping AUTH's Solution spec (stage 30c) — the first module to actually need to *implement* agent status transitions — a real operational gap surfaced: `rejected` means "never approved." There was no way to represent an agent who *was* approved and later needs to be cut off (quit, turned out unreliable, etc.) without either abusing `rejected` (semantically wrong — it implies they were never good) or silently inventing an untracked ad-hoc state, which is exactly the vocabulary drift stage 20's own rules exist to prevent.

## Impact

- `business-requirements.md`'s Domain Vocabulary section and `docs/domain-glossary.md`'s Delivery Agent status entry both under-specify the real lifecycle.
- No FR/AC currently describes admin deactivating an approved agent — this is a new requirement, not just a vocabulary fix.
- No downstream doc yet depends on the old 3-value enum (AUTH's solution.md is being authored in the same session this gap was found, before any TRD/task/code exists), so this is the cheapest possible point to fix it — no code or tests to retrofit.

## Proposed resolution

Add a fourth canonical status, `deactivated`, to the Delivery Agent lifecycle: `pending_approval` → `approved` → (`deactivated` | stays `approved`), with `rejected` remaining a terminal state reachable only from `pending_approval`. Add one new functional requirement (admin can deactivate an approved agent) and its acceptance criterion. Update the domain glossary to match. This is additive — no existing FR, AC, or UC is contradicted or removed.

## Change Summary

### Changes to `docs/business-requirements.md`
- §Domain Vocabulary: extend "Delivery Agent status" from 3 values to 4 (`pending_approval`, `approved`, `deactivated`, `rejected`), with the state-machine note that `deactivated` is reachable only from `approved`.
- §Functional Requirements: add FR-029 — Admin can deactivate a currently-approved delivery agent, immediately preventing new assignments.
- §Acceptance Criteria: add AC-029 for FR-029.
- Cognition graph: no existing node changes required — this doesn't touch any UC/Decision/OpenQuestion already drawn there; the new FR is added to the FR table only, consistent with how FR-027/028 (also cross-cutting, not UC-graph-specific) were handled.

### Changes to `docs/domain-glossary.md`
- §Delivery Agent → "Delivery Agent status": extend definition to the 4-value lifecycle with the same transition note.
